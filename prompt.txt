Build a full-stack AI Sprint Manager system — an Agentic Scrum Master that
automates Agile workflows using multi-agent AI architecture with Jira integration.

--------------------------------------------------------------------------------
PROJECT OVERVIEW
--------------------------------------------------------------------------------

The AI Sprint Manager is an intelligent project management system that acts as a
virtual Scrum Master. It automates sprint planning, task breakdown, story point
estimation, developer assignment, progress monitoring, delay prediction, and
sprint reporting — all connected to Jira via REST API.

The most critical feature is the Automatic Employee Selector: when a task is
created or scheduled, the system automatically assigns the best available
developer based on their tech stack match, merit score, current workload, and
real-time availability — with zero human intervention.

SYSTEM ARCHITECTURE — BUILD THESE COMPONENTS
--------------------------------------------------------------------------------

Build the following 7 AI agents, each as an independent microservice:

1. REQUIREMENT AGENT
   - Accepts raw text input from a Product Manager
   - Uses LLM to parse intent, scope, and acceptance criteria
   - Outputs structured requirement objects
   - Connects to Jira to read existing backlog context

2. TASK GENERATOR AGENT
   - Takes structured requirements from Requirement Agent
   - Generates Agile user stories with acceptance criteria
   - Creates sub-tasks for each story (API, UI, tests, docs)
   - Pushes generated stories to Jira backlog via API

3. STORY POINT ESTIMATOR AGENT
   - Fetches historical sprint data from Jira for training
   - Trains an XGBoost regression model on task complexity patterns
   - Predicts story points (1, 2, 3, 5, 8, 13) for new tasks
   - Updates Jira ticket with the predicted estimate

4. ASSIGNMENT AGENT (Most Important — build this carefully)
   - Implements the full Smart Assignment Engine (see details below)
   - Reads developer profiles from PostgreSQL database
   - Filters by tech stack match, then availability, then merit score
   - Assigns task in Jira and notifies developer via Slack
   - Logs every assignment decision for merit score recalculation

5. SPRINT MONITOR AGENT
   - Listens to GitHub webhooks for commits and pull requests
   - Polls Jira every hour for task status changes
   - Calculates current sprint velocity vs required velocity
   - Fires delay alerts when sprint falls behind threshold
   - Suggests specific corrective actions (move task, reassign, etc.)

6. REPORTING AGENT
   - Triggers automatically at sprint end
   - Pulls all sprint data from Jira
   - Calculates: velocity, completion rate, bottlenecks, top performers
   - Generates burndown charts and velocity trend graphs
   - Creates and publishes sprint report to Confluence or as PDF

7. JIRA SYNC AGENT
   - Handles all bidirectional communication with Jira REST API
   - Reads: backlog items, user stories, story points, sprint details,
     issue status, assignees, bug reports, commit links
   - Writes: new tasks, assignees, story point estimates, sprint status,
     sprint reports, blocker tickets
   - Runs on a queue to handle rate limiting gracefully

AUTOMATIC EMPLOYEE SELECTOR — DETAILED IMPLEMENTATION
--------------------------------------------------------------------------------

This is the flagship feature. Implement it exactly as described:

DEVELOPER PROFILE SCHEMA (store in PostgreSQL):
{
  developer_id: string,
  name: string,
  role: string,
  tech_stack: string[],          // verified skills list
  merit_score: float,            // 0-100, recalculated each sprint
  current_sprint_load: int,      // story points currently assigned
  max_sprint_capacity: int,      // maximum story points per sprint
  availability: {
    status: "available" | "on_leave" | "at_capacity",
    leave_dates: date[],
    daily_hours: int
  },
  performance_history: {
    avg_completion_rate: float,
    avg_code_quality: float,
    avg_pr_review_hours: float,
    sprints_over_capacity: int   // used for burnout detection
  }
}

MERIT SCORE CALCULATION (recalculate after every sprint):
merit_score = (
  tech_stack_match   * 0.25 +   // % of required skills developer has
  completion_rate    * 0.25 +   // % of tasks finished on time
  code_quality_score * 0.20 +   // SonarQube + PR review scores
  pr_review_speed    * 0.15 +   // inverse of avg hours to merge PRs
  peer_rating        * 0.15     // 0-100 from retrospective surveys
)

ASSIGNMENT DECISION ALGORITHM:
Step 1 - Tech Stack Filter:
  query all developers WHERE tech_stack contains ALL required task tags

Step 2 - Availability Check:
  filter WHERE status = "available"
  AND current_sprint_load < max_sprint_capacity
  AND today NOT IN leave_dates

Step 3 - Merit Score Ranking:
  sort remaining developers by merit_score DESC
  apply task-type weighting (e.g. backend tasks weight backend experience higher)

Step 4 - Workload Balancing:
  among top 3 ranked, select developer with lowest current_sprint_load percentage

Step 5 - Assignment:
  update Jira ticket assignee field via REST API
  increment developer current_sprint_load by task story points
  send Slack notification to developer
  log assignment in assignment_history table

Step 6 - Fallback:
  if no developer passes all filters, create alert for PM
  suggest next available date or next sprint scheduling
  never leave task silently unassigned

ADDITIONAL FEATURES TO IMPLEMENT
--------------------------------------------------------------------------------

DEVELOPER BURNOUT DETECTOR:
- Track story points assigned per developer per sprint in performance_history
- If a developer exceeds 100% capacity for 2 or more consecutive sprints,
  set a burnout_risk flag on their profile
- Reduce their assignment_weight by 30% for the next sprint automatically
- Send private alert to manager with workload history chart

STANDUP SUMMARIZER:
- Create a Slack slash command /standup
- When triggered, AI reads the last 24 hours of messages in the standup channel
- Extracts: completed work, planned work, blockers per team member
- Posts a formatted summary and creates Jira tickets for any blockers found

SKILL GAP ANALYZER:
- Log every failed assignment attempt in skill_gap_log table
- Run a weekly job that queries skill_gap_log for patterns
- If the same skill appears as missing 3+ times in one month,
  generate a skill gap report and email it to the engineering manager

SELF-LEARNING MODEL:
- After every sprint closes, run a retraining pipeline
- Compare predicted story points vs actual story points delivered
- Compare predicted delays vs actual delays that occurred
- Retrain XGBoost model with new sprint data appended to training set
- Save new model version with performance metrics in model_versions table
- Automatically activate new model if it performs better than previous version
