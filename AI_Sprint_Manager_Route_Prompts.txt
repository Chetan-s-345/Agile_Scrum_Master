PROMPT 02 — NEON DB BRANCH MANAGER (Core Multi-Org Engine)
████████████████████████████████████████████████████████████████████████████████
================================================================================

Build the Neon DB Branch Manager for an AI Sprint Manager SaaS. This is the
core system that creates an isolated Neon database branch for every new
organization that signs up, and manages connections to each branch.

---

FILE: src/config/neon.js

Build a NeonBranchManager class with these methods:

1. createOrgBranch(orgId, orgSlug)
   - Calls POST https://console.neon.tech/api/v2/projects/{NEON_PROJECT_ID}/branches
   - Request body:
     {
       branch: {
         name: "org-{orgSlug}-{orgId.slice(0,8)}",
         parent_id: NEON_BASE_BRANCH_ID   // clone from base schema branch
       },
       endpoints: [{ type: "read_write", autoscaling_limit_min_cu: 0.25 }]
     }
   - Headers: Authorization: Bearer NEON_API_KEY
   - Wait for branch to be ready (poll GET /branches/{branchId} until ready)
   - Extract connection string from response endpoints
   - Return: { branchId, branchName, connectionString, host }

2. getOrgConnectionString(orgId)
   - Calls GET https://console.neon.tech/api/v2/projects/{id}/branches
   - Find branch named "org-*-{orgId.slice(0,8)}"
   - Get its endpoint connection URI
   - Return connection string

3. deleteBranch(branchId)
   - Calls DELETE https://console.neon.tech/api/v2/projects/{id}/branches/{branchId}
   - Used when org is deleted or subscription cancelled

4. suspendBranch(branchId)
   - Calls POST .../branches/{branchId}/endpoints/{endpointId}/suspend
   - Used when org subscription expires to pause DB and stop billing

5. resumeBranch(branchId)
   - Calls POST .../branches/{branchId}/endpoints/{endpointId}/resume
   - Used when org reactivates subscription

6. listAllBranches()
   - Returns all branches for the Neon project
   - Maps each to: { branchId, name, orgId, createdAt, state }

7. getBranchMetrics(branchId)
   - Calls GET .../branches/{branchId}/metrics
   - Returns compute time, data transfer, storage used

Include:
- Retry logic (3 retries with exponential backoff) for all API calls
- Axios instance with base URL and auth header pre-configured
- Polling helper that checks branch state every 2 seconds, times out at 60s
- Error classes: NeonApiError, BranchCreationError, BranchNotFoundError

---

FILE: src/config/database.js

Build a DatabasePoolManager class:

1. universalPool
   - Single pg.Pool connected to UNIVERSAL_DATABASE_URL
   - Max 20 connections
   - Used for: orgs, users, billing, sessions, audit

2. getOrgPool(orgId)
   - Check in-memory Map for existing pool
   - If not found: query universal DB for org's connectionString
   - Create new pg.Pool with that connection string
   - Max 10 connections per org pool
   - Set idleTimeoutMillis: 30000
   - Store in Map with orgId key
   - Return pool

3. releaseOrgPool(orgId)
   - End pool and remove from Map
   - Called when org is inactive

4. query(pool, sql, params)
   - Wrapper around pool.query with error logging

5. transaction(pool, callback)
   - Runs callback inside BEGIN/COMMIT/ROLLBACK block
   - callback receives a client for making queries

---

FILE: src/middleware/orgDb.js

Build Express middleware orgDbMiddleware:
- Extract orgId from req.user.orgId (set by auth middleware)
- Call DatabasePoolManager.getOrgPool(orgId)
- Attach pool to req.orgDb
- Attach helper: req.orgQuery(sql, params) = pool.query(sql, params)
- Call next()
- On error: return 503 with message "Database unavailable"

FILE: src/routes/auth.routes.js
Mount at: /api/v1/auth

BUILD THESE ENDPOINTS:

POST /register
- Body: { email, password, fullName, orgName, orgSlug, planSlug? }
- Validate with zod: email format, password min 8 chars, orgSlug alphanumeric
- Check email not already in global_users
- Check orgSlug not already in organizations
- Hash password with bcrypt (rounds: 12)
- In a universal DB transaction:
  1. INSERT into global_users
  2. INSERT into organizations (status: trial, trial_ends_at: NOW()+14days)
  3. INSERT into org_members (role: owner)
  4. INSERT into subscriptions (plan: free by default)
- Trigger Neon branch creation:
  5. Call NeonBranchManager.createOrgBranch(orgId, orgSlug)
  6. Save connectionString back to organizations.db_connection_string
  7. INSERT into db_provisioning_log (status: success)
- Run org schema seed: insert org_settings row into new branch
- Generate JWT + refresh token
- Return: { user, org, tokens }
- On Neon failure: rollback org creation, return 503

POST /login
- Body: { email, password, orgSlug? }
- Find user in global_users by email
- Check is_active and not locked
- Compare password with bcrypt
- If orgSlug provided: verify org_members membership
- If user belongs to multiple orgs and no orgSlug: return list of orgs to pick
- Update last_login_at, last_login_ip
- INSERT into auth_sessions
- Return: { user, org, tokens }

POST /refresh
- Body: { refreshToken }
- Verify refresh token signature and expiry
- Find session in auth_sessions
- Issue new access token
- Rotate refresh token (update in auth_sessions)
- Return: { accessToken, refreshToken }

POST /logout
- Auth required
- Set auth_sessions.is_active = FALSE for current session
- Return: 200 OK

POST /forgot-password
- Body: { email }
- Find user, generate secure token with crypto.randomBytes(32)
- Hash token, INSERT into password_resets
- Send email (log to console in dev)
- Return 200 always (no user enumeration)

POST /reset-password
- Body: { token, newPassword }
- Hash token, find in password_resets where used=FALSE and not expired
- Update global_users.password_hash
- Mark password_resets.used = TRUE
- Invalidate all existing auth_sessions
- Return 200

POST /verify-email
- Body: { token }
- Find and validate token
- Update global_users.email_verified = TRUE

GET /me
- Auth required
- Return current user + org memberships

FILE: src/routes/assignment.routes.js
Mount at: /api/v1/assignment
All routes: auth middleware + orgDb middleware

BUILD THESE ENDPOINTS:

POST /assign
- Body: { taskId, sprintId, techTags[], storyPoints, priority }
- This is the core Smart Assignment Engine endpoint
- Run the full assignment algorithm:

  STEP 1 — Tech Stack Filter:
  SELECT dp.* FROM developer_profiles dp
  WHERE dp.tech_stack @> $techTags   -- GIN index on tech_stack array
  AND dp.availability_status = 'available'

  STEP 2 — Availability Filter:
  For each matched developer:
  - Check current_sprint_load + storyPoints <= max_sprint_capacity
  - Check no leave in developer_availability overlapping sprint dates
  - Remove developers who fail either check

  STEP 3 — Merit Score Ranking:
  Sort remaining developers by:
  (merit_score * assignment_weight) DESC

  STEP 4 — Workload Balance:
  Among top 3 ranked:
  - Calculate remaining_capacity = max_sprint_capacity - current_sprint_load
  - Pick developer with highest remaining_capacity

  STEP 5 — Assign:
  - UPDATE tasks SET assignee_id, assigned_by='ai', assigned_at=NOW()
  - UPDATE developer_profiles SET current_sprint_load += storyPoints
  - INSERT into assignment_log with all scores and reasoning
  - Call Jira service to update assignee (if Jira connected)
  - Call Slack service to notify developer (if Slack connected)

  STEP 6 — Fallback:
  If no developer passes all filters:
  - INSERT into assignment_failures with reason_code and details
  - Return 200 with { assigned: false, reason, suggestion }

- Return: { assigned: true, developer, scores, reason }

POST /assign-bulk
- Body: { tasks: [{ taskId, techTags[], storyPoints }] }
- Run assignment for multiple tasks in priority order
- Balance workload across sprint — do not assign all to same person
- Return: { results: [{ taskId, assigned, developer?, reason }] }

POST /reassign
- Body: { taskId, reason }
- Exclude current assignee from candidates
- Run assignment algorithm again
- UPDATE previous assignment_log outcome
- Log reassignment event

GET /suggest/:taskId
- Do not assign — just return ranked list of candidates
- Show: developer name, meritScore, techMatch%, currentLoad, available
- Useful for manual assignment with AI recommendations

GET /failures
- Return recent assignment_failures that are unresolved
- Group by reason_code
- Include suggestion for each

GET /log
- Return assignment_log with pagination
- Filter: ?developerId=&sprintId=&from=&to=
- Include: task title, developer name, score breakdown, outcome

FILE: src/services/monitoringService.js

Build a MonitoringService class with these methods:

1. takeDailySnapshot(sprintId, orgPool)
   - Calculate day_number (sprint start to today)
   - ideal_points_remaining = planned_points - (planned_points/sprint_days * day_number)
   - actual_points_remaining = planned_points - completed_points
   - current_velocity = completed_points / day_number
   - required_velocity = actual_points_remaining / remaining_days
   - velocity_gap_pct = ((required_velocity - current_velocity) / required_velocity) * 100
   - delay_risk_score = weighted combination of velocity_gap, blocked_count, team_availability
   - delay_predicted_days = MAX(0, (actual_remaining/current_velocity) - remaining_days)
   - INSERT into sprint_progress_snapshots
   - Call checkDelayThreshold(sprintId, velocity_gap_pct, orgPool)

2. checkDelayThreshold(sprintId, velocityGapPct, orgPool)
   - Get threshold from org_settings.delay_alert_threshold (default 20%)
   - If velocityGapPct > threshold:
     - Find tasks most at risk (in_progress longest without update)
     - INSERT into delay_alerts with severity based on gap %
     - If gap > 40%: severity='critical', else 'warning'
     - Generate suggestion: which task to move, who to reassign
   - Check for tasks past due_date: INSERT individual task alerts

3. runAllActiveSprintSnapshots()
   - Query universal_db for all active orgs
   - For each org: get org pool, query active sprints, call takeDailySnapshot
   - This runs via Bull cron job every day at 9 AM UTC
